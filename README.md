# PulseBot — بوت تيليجرام مجاني لمتابعة الأسهم الأمريكية

بوت **مجاني بالكامل** يعمل على GitHub Actions، يرسل لك على تيليجرام ملخصات ومستويات مرجعية لـ 19 سهماً ومؤشراً.
- **بدون ذكاء اصطناعي**: كل قاعدة معادلة ثابتة مكتوبة هنا، ونفس البيانات تعطي نفس الرسالة دائماً.
- **بدون إشارات شراء/بيع**: الأهداف تُعطى للسيناريوهين (صعود وهبوط) كمستويات مرجعية فقط.
- **منفصل تماماً** عن سكربتات TradingView (محمد و ICT-Boom) ولا يلمسها.

> ⚠️ معلومة تعليمية وليست توصية. الإحصائيات التاريخية تحت مكتوبة بصراحة، وأغلبها **لا يُظهر أفضلية** على الصدفة.

## 1) خطوات التشغيل (مرة واحدة، حوالي 15 دقيقة)

### أ) حساب GitHub ومستودع عام
1. سجّل في https://github.com (مجاني).
2. اضغط **New repository**، سمّه مثلاً `pulsebot`، واختر **Public**.
   (المستودع العام يعطي دقائق GitHub Actions مجانية بلا حد. المستودع الخاص له 2000 دقيقة شهرياً، والبوت يحتاج تقريباً 1,500–2,500 دقيقة، لذلك العام أضمن.)
3. ارفع كل ملفات هذا المجلد (ماعدا `data_cache/`) إلى المستودع: **Add file → Upload files**، أو عبر git.
   تأكد أن المجلد `.github/workflows/` انرفع (فيه `pulse.yml` و `tests.yml`).

### ب) إنشاء البوت في تيليجرام (TELEGRAM_TOKEN)
1. افتح تيليجرام وابحث عن **@BotFather**.
2. أرسل `/newbot`، واختر اسماً ثم اسم مستخدم ينتهي بـ `bot`.
3. سيعطيك **توكن** بالشكل `123456789:ABC...`. هذا هو `TELEGRAM_TOKEN`. لا تشاركه مع أحد.

### ج) معرفة رقم المحادثة (CHAT_ID)
1. افتح البوت الجديد في تيليجرام واضغط **Start** وأرسل أي رسالة (مثلاً `/مساعدة`).
2. افتح في المتصفح: `https://api.telegram.org/bot<TOKEN>/getUpdates` (ضع التوكن مكان `<TOKEN>`).
3. ابحث عن `"chat":{"id": 123456789` — هذا الرقم هو `CHAT_ID`.
   (لو تبيه في مجموعة: أضف البوت للمجموعة وأرسل رسالة فيها؛ رقم المجموعة يبدأ بـ `-`.)

### د) إضافة الأسرار (Secrets)
في المستودع: **Settings → Secrets and variables → Actions → New repository secret**:
| الاسم | القيمة |
|---|---|
| `TELEGRAM_TOKEN` | التوكن من BotFather |
| `CHAT_ID` | رقم المحادثة |

الأسرار لا تظهر لأحد حتى في المستودع العام.

### هـ) تفعيل الـ workflow
1. تبويب **Actions** → إذا طلب، اضغط **I understand my workflows, go ahead and enable them**.
2. **Settings → Actions → General → Workflow permissions** → اختر **Read and write permissions** (للالتزام الأسبوعي).
3. اختبار يدوي: **Actions → pulsebot → Run workflow**. خلال ساعات السوق تصل الرسائل؛ خارجها يرد فقط على الأوامر.
4. بعدها يعمل تلقائياً كل 10 دقائق أيام الأسبوع.

### و) التجربة على جهازك بدون إرسال (اختياري)
```
pip install -r requirements-dev.txt
python -m pytest -q tests              # الاختبارات
python -m pulsebot run                  # تشغيل حقيقي للبيانات، لكن تجريبي للإرسال (يكتب في samples/outbox_live_dryrun.jsonl)
python tools/fetch_history.py           # تنزيل بيانات تاريخية إلى data_cache/
python -m pulsebot replay 2026-10-01    # إعادة يوم كامل من البيانات المخزنة (لا شيء يُرسل)
```
الإرسال الحقيقي يحصل **فقط** إذا كان `PULSEBOT_LIVE=1` والتوكن ورقم المحادثة موجودين (هذا يضبطه `pulse.yml`).

## 2) كيف يعمل
- **الجدولة**: GitHub يشغّل البوت كل 10 دقائق من 13:00 إلى 21:59 UTC أيام الاثنين–الجمعة. هذا يغطي 09:00–16:30 بتوقيت نيويورك صيفاً وشتاءً، والكود نفسه (zoneinfo) يقرر هل هو وقت عمل؛ فالتوقيت الصيفي محسوب تلقائياً.
- **العطل**: قائمة عطل بورصة نيويورك لـ 2026–2027 داخل `pulsebot/market_time.py` (والأيام المختصرة تغلق 13:00).
- **البيانات**: yfinance فقط (1H + يومي + 5 دقائق)، دفعات من 10 أسهم، 3 محاولات مع انتظار متزايد (4 ثم 8 ثم 12 ثانية) للأسهم الناقصة فقط؛ لو بقي سهم بدون بيانات تصلك رسالة مشكلة تقنية بالعربي (مرة واحدة كل ساعة). لا يوجد مصدر بديل.
- **الملخصات**: رسالة **واحدة** لكل الأسهم عند إغلاق كل شمعة ساعة (10:30، 11:30 … 15:30، 16:00)، سطران لكل سهم. التفاصيل الكاملة لأي سهم عند الطلب: `/الملخص NVDA`. أما **الأهداف والوقف فتُفحص كل تشغيل** باستخدام أعلى/أدنى سعر منذ آخر فحص (شموع 5 دقائق)، فلا يفوت لمس حصل بين تشغيلين.
- **منع التكرار**: ملف الحالة `state/state.json` يحفظ ما أُرسل، ويُحفظ بين التشغيلات عبر GitHub cache.
- **الالتزام الأسبوعي**: مرة كل أسبوع يكتب `state/heartbeat.txt` ويعمل commit، حتى لا يوقف GitHub الجدولة (يوقفها بعد 60 يوماً بلا نشاط).
- **حجم الرسائل** (بعد التعديل): في إعادة 8 أيام تداول (2026-09-22 → 10-01): أقل يوم 19، المتوسط 22.6، أكثر يوم 29 رسالة تلقائية (بدل 255–283 قبل التعديل):
  - الملخص كل ساعة: رسالة واحدة لكل شمعة (7 يومياً).
  - ملاحظات الوقف + الأهداف: رسالة واحدة بعد الساعة الأولى ورسالة واحدة بعد الساعة الثانية، **للأسهم البارزة فقط**.
  - تحقق الأهداف / ضرب الوقف / إلغاء الملاحظة: تُرسل فوراً، وكل أحداث نفس التشغيل في رسالة واحدة.
  - تغيّر الاتجاه، التقلب العالي، الخطط المنتهية: أحداث نفس التشغيل في رسالة واحدة.
  - رسالة الصباح، ملخص نهاية اليوم، المشاكل التقنية: كما هي.
  - إذا تجاوزت رسالة حد تيليجرام (4096) تُقسم بين الأسهم فقط وليس في منتصف سهم، ويُكتب "(جزء 1 من 2)". الطول يُحسب على نص HTML الخام **مع الوسوم** وبوحدات UTF-16 مثل تيليجرام (الإيموجي = 2)، والحد المستخدم 3900، فالنص الظاهر دائماً أقل من الحد بهامش.
- **التنسيق** (`parse_mode=HTML`):
  - كل رسالة مجمّعة: سطر عنوان عريض، ثم سطر الوقت/العدد (🔢)، ثم كتلة لكل سهم يفصل بينها خط `━` .
  - طول الخط = `SEPARATOR_LEN` في `config.py` (الافتراضي 24؛ جرّب 20 أو 28)، أو بمتغير البيئة `PULSEBOT_SEPARATOR_LEN`.
  - اسم السهم **عريض**، وكل معلومة في سطر قصير مستقل.
  - كل نص متغير (أسماء، أسعار، عناوين أخبار) يُهرَّب (`<` `>` `&`) قبل الإرسال.
  - لو رفض تيليجرام HTML (خطأ 400 "can't parse") تُعاد نفس الرسالة كنص عادي بدون وسوم.
  - الربح/الخسارة في رسائل الأهداف والوقف تُكتب حسب السيناريو: "الربح للصعود" أو "الربح للهبوط"؛ الموجب = في صالح السيناريو. مثال هبوط: الدخول $249.18 والسعر $248.00 ← "الربح للهبوط: +$1.18".
  - رسائل الصباح ونهاية اليوم والمشاكل التقنية و`/الحالة` بنفس الأسلوب (عنوان عريض وخطوط فاصلة بين الأقسام).
- **السهم البارز** (معادلة صريحة، `NOTABLE_RULE` في `config.py`):
  `بارز = تقلب_عالٍ_اليوم أو تغيّر_اتجاه_اليوم أو خطة_مفتوحة`
  - `تقلب_عالٍ_اليوم`: درجة التقلب (ATR14 ÷ ATR100، ترتيبها بين آخر 252 يوم) ≥ 80% — نفس شرط رسالة 4.
  - `تغيّر_اتجاه_اليوم`: حصل تغيّر اتجاه على فريم الساعة (رسالة 3) اليوم في شمعة الملاحظة أو قبلها.
  - `خطة_مفتوحة`: للسهم خطة مرجعية مفتوحة (الخطط تُبنى بعد الساعة الأولى، فهذا الشرط يهم بعد الساعة الثانية).
  - إذا لا يوجد سهم بارز تصل رسالة قصيرة واحدة تقول ذلك.
- **حد الإرسال**: رسالة كل 1.2 ثانية على الأقل، وحد أقصى 60 رسالة لكل تشغيل (الباقي ينتقل للتشغيل التالي)، واحترام `retry_after` من تيليجرام.

## 6) كل القواعد كمعادلات
الرموز: `O` افتتاح، `H` أعلى، `L` أدنى، `C` إغلاق، `SMA20` متوسط آخر 20 إغلاق، `ATR14` متوسط المدى الحقيقي (Wilder).

- **المدى الحقيقي**: `TR = max(H − L, |H − C_prev|, |L − C_prev|)`؛ `ATR14_t = (ATR14_{t−1}·13 + TR_t) / 14`.
- **الاتجاه** (شهري/أسبوعي/يومي/ساعة، على شموع مكتملة فقط):
  صاعد 🟢 إذا `C > SMA20` **و** `SMA20 > SMA20 قبل 5 شموع`؛ هابط 🔴 بالعكس؛ غير ذلك محايد ⚪؛ "بيانات غير كافية" إذا أقل من 25 شمعة.
  الخلاصة تُكتب بالعد: "3 من 4 صاعدة".
- **الحركة المعتادة لليوم**: `±ATR14 اليومي` بالدولار وكنسبة من السعر.
- **المستويات**: أقرب رقم دائري فوق/تحت السعر؛ قمة/قاع أمس؛ قمة/قاع الأسبوع الماضي؛ افتتاح اليوم والشهر.
  **الرقم الدائري**: الخطوة = أكبر قيمة من {0.5، 1، 2.5، 5، 10، 25، 50، 100، 250} لا تتجاوز 1% من السعر.
- **القمة/القاع المتأرجح (1H)**: قمة عند الشمعة i إذا `H_i > max(H_{i−3..i−1})` و `H_i ≥ max(H_{i+1..i+3})`، ولا تُعتمد إلا بعد إغلاق الشموع الثلاث بعدها (بدون إعادة رسم).
- **تغيّر الاتجاه (3)**: شمعة ساعة **مكتملة** تغلق فوق آخر قمة متأرجحة معتمدة (صاعد) أو تحت آخر قاع (هابط)، والهيكل السابق عكسها. أول كسر يحدد الهيكل فقط بدون تنبيه.
- **الحركة الكبيرة (4)**: `نسبة = ATR14 ÷ ATR100` (يومي). `الدرجة = نسبة الأيام من آخر 252 يوم التي نسبتها ≤ نسبة اليوم`. تنبيه إذا `الدرجة ≥ 80%` (أعلى 20%). بدون اتجاه، وينتهي بنهاية اليوم.
- **ملاحظة الوقف (5)** بعد الساعة 1 (10:30) والساعة 2 (11:30):
  إذا `سعر الإغلاق > افتتاح اليوم` → الوقف = `أدنى سعر منذ الافتتاح`؛ إذا `<` → الوقف = `أعلى سعر منذ الافتتاح`.
- **إلغاء الملاحظة (6)**: إذا رجع السعر عبر الافتتاح (تحت الافتتاح لملاحظة الصعود، فوقه لملاحظة الهبوط).
- **الأهداف (7)** عند الساعة 1، للسيناريوهين، الدخول المرجعي = إغلاق شمعة 10:30، `المسافة الدنيا = 0.10 × ATR اليومي`:
  - `T1` = الأقرب من {الرقم الدائري التالي، قمة أمس (صعود)/قاع أمس (هبوط)} بشرط أن يبعد أكثر من المسافة الدنيا.
  - `T2` = قمة/قاع الأسبوع الماضي إذا كان بعد T1 بأكثر من المسافة الدنيا، وإلا الرقم الدائري التالي بعد T1.
  - `T3` = `افتتاح اليوم ± ATR اليومي` (غير متاح إذا تجاوزه السعر).
  - `المسافة = |الهدف − الدخول|`؛ `المضاعف = المسافة ÷ |الدخول − الوقف|`؛ `نسبة الصدفة = 1 ÷ (1 + المضاعف)`.
  - تحذير إذا `مسافة الوقف < 0.05 × ATR اليومي`.
- **المتابعة (8–12)** كل تشغيل على أعلى/أدنى منذ آخر فحص:
  - لمس الهدف = `أعلى ≥ الهدف` (صعود) أو `أدنى ≤ الهدف` (هبوط)؛ كل هدف يُحسب لما يُلمس.
  - **إذا لُمس الوقف وهدف في نفس نافذة الفحص → يُحسب وقف** (تحفّظ).
  - بعد T1: الوقف ← سعر الدخول؛ بعد T2: الوقف ← T1 (فقط إذا يضيّق الوقف).
  - الخطة تنتهي عند الوقف، أو عند لمس كل الأهداف، أو بنهاية اليوم (12).

**الخلاصة: النسب ≈ نسبة الصدفة أو أقل، فالأهداف لا تعطي أفضلية إحصائية.** هي مسافات مرجعية لإدارة المخاطرة. النتائج ثابتة بين نصفي الفترة.

**الحركة الكبيرة** (20 سنة، 18 سهماً): في أيام أعلى 20%، مدى اليوم ≥ 1.5×ATR حصل 9.9% مقابل 8.2% في باقي الأيام، ومتوسط المدى 0.95 ATR مقابل 0.92. يعني أن الحركة أكبر **بالدولار** فقط لأن ATR نفسه مرتفع، و**لا** يتوقع حركة استثنائية. يمكنك إيقافه: `/تبديل big_move إيقاف`.

## 8) القيود والمشاكل المعروفة
1. **تأخر GitHub**: الجدولة قد تتأخر 5–20 دقيقة وقت الزحمة، وقد يُتخطى تشغيل أحياناً. البوت يعوّض بفحص أعلى/أدنى منذ آخر فحص، لكن وقت الرسالة يتأخر.
2. **حجم الرسائل**: بعد التجميع 19–29 رسالة يومياً (متوسط 22.6، بتنسيق HTML الجديد) في الأيام الثمانية المُعادة (`samples/messages_per_day.txt`). عدد الأسهم البارزة كان 2–7؛ رسائل الوقف والأهداف انقسمت لأجزاء في 4 من 8 أيام (التنسيق الجديد سطر لكل معلومة فهو أطول؛ ملخص الساعة لـ 19 سهماً ≈ 3,480 من 3,900 فلم ينقسم). لإرجاع رسالة لكل سهم: أوقف `summary_consolidated` أو `notes_consolidated` أو `batch_events`.
3. **مصدر بيانات واحد**: لا يوجد بديل لـ yfinance؛ إذا تعطّل Yahoo تصلك رسالة المشكلة التقنية فقط ولا تصل ملخصات حتى يعود.
4. **yfinance غير رسمي**: Yahoo قد يغيّر أو يحد الطلبات. البيانات قد تتأخر دقائق.
5. **قائمة العطل** لـ 2026–2027 فقط: يجب تحديثها سنوياً في `market_time.py`.
6. **الحالة في GitHub cache**: إذا حُذف الـ cache (بعد 7 أيام بلا استخدام) يبدأ البوت من جديد بدون إرسال مكرر لتنبيهات الاتجاه، لكن قد يُعاد ملخص الساعة الأخيرة.
7. **SPCX** (إدراج يونيو 2026) تاريخه قصير: الاتجاه الشهري/الأسبوعي "بيانات غير كافية"، وبدون درجة تقلب.
8. **الأخبار** من Yahoo عبر yfinance، إنجليزية، وأي فشل يُتجاهل بصمت (يُسجّل في السجل فقط).
9. الإحصائيات محسوبة على فترة محدودة (~3 سنوات ساعة)، والماضي لا يضمن المستقبل.
10. الأسهم غير البارزة لا تصلها ملاحظات وقف أو أهداف (هذا مقصود لتقليل الرسائل)؛ استخدم `/الملخص SYMBOL` أو أوقف `notable_only`.
11. لو ربطت البوت بـ webhook في مكان آخر، `getUpdates` لا يعمل والأوامر لن تصل.
